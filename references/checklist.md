# 检查清单 / checklists

打印出来打勾，或者在动手前逐条过一遍。每一条都对应过真实事故。

---

## A. 动手前（10 分钟，只读）

| # | 检查 | 命令 / 位置 |
|---|---|---|
| A1 | 库文件齐全，头文件读完，知道公开 API | `ls`、读 `.h` |
| A2 | 库分几层？哪些与板子无关（协议层）、哪些必须绑定引脚 | 看 `#include`、宏 |
| A3 | 库需要哪些资源：外设、DMA、中断、回调、线程、GPIO | 列一张表 |
| A4 | 目标工程的构建系统与根目录 | `scan_project.py` |
| A5 | 目标工程已有的 UART / DMA / IRQHandler / HAL 回调 | 同一个扫描器 |
| A6 | 目标工程里是否已经有这个库的接入代码 | `--grep "库前缀"` |
| A7 | 是否 CubeMX 生成（有没有 USER CODE 锚点、`.ioc`） | 扫描器 |
| A8 | 是否 RTOS、任务创建在哪 | `freertos.c` / `osThreadNew` |
| A9 | 备份放哪、会不会被扫描器扫到 | 选 `MDK-ARM/<LIB>_backup` |
| A10 | 用户是否接受"动 4 个文件"（驱动目录、回调文件、freertos.c、uvprojx） | 先说明，再动手 |

## B. 写配置器时（B 类任务）

| # | 检查 |
|---|---|
| B1 | 支持 `--dry-run`，默认不写 |
| B2 | 有 GUI（路径输入 + 浏览 + 一键 + 日志）和 CLI 两种入口 |
| B3 | 参数集中在 `config.json`，改参数不用改 Python |
| B4 | 每个插入片段带唯一 marker，重跑幂等 |
| B5 | 每次写文件前备份，保留相对路径 |
| B6 | `.uvprojx` 写完先 XML 校验，失败不落盘 |
| B7 | 生成文件头写"整份覆盖"警告 |
| B8 | 检测到重复接入（旧代码还在）时只同步、不接线 |
| B9 | 报告文件写出改动明细 + 下一步 |
| B10 | 中文日志不炸（`sys.stdout.reconfigure(encoding="utf-8")`） |

---

## C. 交付前（C 类 / 直接配置）

| # | 检查 | 怎么验 |
|---|---|---|
| C1 | 在**副本**上跑过，没动用户真实工程 | `robocopy /XD Drivers Middlewares` |
| C2 | 更新 / 新建的文件都在预期位置 | `git status` 或 `ls` |
| C3 | 中断函数没有重复定义 | grep `*_IRQHandler` |
| C4 | HAL 回调只有一份（转发或定义，二选一） | grep `HAL_UARTEx_RxEventCallback` |
| C5 | `uvprojx` 是合法 XML，`<File>` 缩进正确 | `ET.parse` + 人眼 |
| C6 | `IncludePath` 包含库目录，且没重复 | 读 XML |
| C7 | 生成的 C 文件括号/注释平衡 | 状态机检查 |
| C8 | 生成代码用到的 HAL 符号在这版 HAL 里存在 | grep `Drivers/` |
| C9 | 重跑一次全部 `[same]` | 幂等 |
| C10 | 备份目录里有原始文件 + 报告 | `ls` |
| C11 | 明确告诉用户：**没有编译、没有上机**，Rebuild 后可能还需要调 ID/引脚 | 写在回复里 |
| C12 | 给用户一条"回滚"路径（备份目录在哪） | 写在回复里 |

## D. 上机前用户自己要做的事（写进交付说明）

| # | 事 |
|---|---|
| D1 | Keil 里 Rebuild，确认新文件参与编译 |
| D2 | 确认设备 ID / 地址与代码里的宏一致（如电机 ID） |
| D3 | 确认总线物理层：A/B 是否接反、是否共地、终端电阻 |

| D5 | 先跑"最安全"的模式（零力矩 / 只读），再上闭环 |
